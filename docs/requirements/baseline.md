## حدود المنتج الثابتة

- Windows Desktop، C# و.NET 8 أو أحدث، WPF وMVVM؛ تشغيل محلي أو شبكة LAN دون خدمة ويب أو اعتماد يومي على الإنترنت.
- SQL Server Express أو إصدار مناسب لحجم العميل؛ لا استبدال بـSQLite ولا نقل تلقائي لنسخة MotoParts من main.
- قاعدة مستقلة لكل تاجر ومنشأة واحدة وفروع متعددة تخصه داخلها، وفق U7 وDEC-005. يبدأ الإعداد بفرع واحد، دون مشاركة بيانات التجار أو دمج قواعدهم. هذا التوضيح الأحدث يستبدل فصل قواعد الفروع في S1 وتفسير U6 السابق؛ الأصول التاريخية محفوظة.
- محاسبة ومخزون ومبيعات ومشتريات ونقدية وPOS ورواتب وتخليص جمركي وتقارير وإدارة وصلاحيات. تعدد القطاعات بإعدادات في الكود نفسه.
- لا تفعيل تجاري أو تقسيم نسخ حسب الميزات الآن. لا VPN أو وصول إلى قاعدة العميل عن بعد أو أدوات دعم فني عن بعد داخل المنتج. بيئة التطوير السحابية ليست نموذج نشر المنتج.
- النسخ الاحتياطي محلي اختياري، والإقفال السنوي اختياري وذاتي التنفيذ بالصلاحيات. إعداد عميل جديد عبر Batch وقاعدة قالب خالية من المعاملات.
- هوية جديدة، عربية وRTL، لوحة مفاتيح وماوس، وواجهات موحدة بدلاً من نسخ الشاشات المتشابهة.

تحديثU2: بلد التشغيل الأول اليمن، والعملات الأولية ريال يمني وريال سعودي ودولار، مع إضافة عملات وتحديد أسعار التحويل. المثال 1USD=3.8SAR سعر توضيحي يحدده المستخدم، لا سعر سوق معتمد ولا قيمة ثابتة للنظام. الضريبة قابلة للتفعيل والتعطيل دون نسبة إلزامية مقررة هنا. التسديد بعملة مختلفة مطلوب منذ الإصدار الأول، مع بقاء تقارير العملات منفصلة. بعد شرح الفرق، اعتمدU3 الجرد المستمر؛ تفاصيل نطاق التكلفة والسالب والأثر الرجعي وتغيير الطريقة تبقى مفتوحة.

## مسؤوليات الطبقات المستهدفة

| الرمز | الطبقة | المسؤولية |
|---|---|---|
| D | Domain | الكيانات والقيم وقواعد التوازن والعملات والكمية والتكلفة وحالات المستند؛ لا SQL ولا WPF |
| A | Application | حالات الاستخدام وDTO والتحقق والصلاحيات وتنسيق المعاملة واختيار استراتيجية الترحيل، عبر عقود |
| I | Infrastructure | EF Core وSQL Server وMigrations وSeed وتنفيذ المعاملات والتزامن وDapper وPDF وExcel والنسخ والملفات |
| W | WPF | Views/ViewModels والتنقل والأوامر وعرض الأخطاء؛ App هو Composition Root لتسجيل الخدمات |

اتجاه الاعتماد: `A → D` و`I → A + D` و`W → A`، ويمكن لـW الإشارة إلىI لتجميع الخدمات فقط. لا وصول إلى قاعدة البيانات من ViewModel. استدعاء التقرير يبدأ فيA لكن تنفيذ Dapper فيI خلف واجهة. موضع Shared وتثبيت الإصدارات قرارات تقنية للمرحلة الثانية (DEC-009).

التقنيات الموثقة: EF Core، Dapper مع Stored Procedures للتقارير الثقيلة، CommunityToolkit.Mvvm، QuestPDF، ClosedXML، ZXing.Net، FluentValidation، AutoMapper، Serilog، BCrypt، xUnit. لا توجد حالياً ملفات حزم تثبت تثبيتها أو توافق إصداراتها؛ الترخيص والتوافق يفحصان عند التثبيت.

## قاموس العمل

- المستند: عملية تجارية/مخزنية محددة بـDocumentTypeId؛ لا نعتمد نص القائمة المعروض لتحديد السلوك.
- الترحيل: اعتماد أثر العملية في الحسابات والمخزون داخل معاملة؛ لا يساوي حفظ مسودة أو الطباعة.
- الإلغاء: تغيير حالة مستند سبق ترحيله مع عكس آثاره اللازمة، دون إزالة الأصل.
- المردود: مستند مستقل مرتبط بالأصل وكمياته وتكلفته؛ ليس حذفاً للبيع أو الشراء.
- القيد: رأس وسطور، له مصدر وفترة، ويحتاج صحة الحسابات والمبالغ والعملات إضافة إلى التوازن.
- سعر الصرف/تكلفة وقت العملية: قيم تاريخية محفوظة، لا يعاد تفسيرها من الإعدادات الحالية.
- الرصيد والإحصائيات: بيانات محسوبة من الحركات وتحدث معها؛ ليست بديلاً عن السجل التاريخي.
- الفترة المالية المغلقة تختلف عن إقفال الصندوق اليومي، وعن نقل أرصدة سنة إلى قاعدة جديدة.
- مخطط/منفذ/متحقق/مقبول حالات مستقلة؛ وجود كود أو شاشة وحده لا يثبت صحة الوظيفة.
