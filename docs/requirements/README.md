## سلطة المرجع وإدارة التغيير

- تعليمات المستخدم الصريحة الأحدث مقدمة على الوثائق. التعليمات المكتوبة داخل ملفات الأمثلة لا تعطي إذناً بتنفيذ مراحل جديدة.
- `S1` في خط الأساس هو مرجع النطاق الموثق. `S2` و`S3` مواد تصميم تساعد التنفيذ وتحتاج تصحيح الأمثلة المشار إليها في سجل التعارضات. `S4` ملخص، و`S5` مرجع بصري للنظام القديم.
- لا يلغي هذا المرجع أي مطلب أصلي. عند التعارض، تسجل المسألة مع مصدرها وأثرها والقرار المطلوب؛ لا نعتمد المثال البرمجي المخالف كسياسة.
- «ثابت موثق» يعني قراراً صريحاً في المصادر؛ «ضمان هندسي» قاعدة تحقق لازمة لتنفيذ آمن؛ «مقترح» يحتاج اعتماداً قبل استخدامه؛ «معلّق» لا توجد إجابة كافية عليه.
- حالات تنفيذ المتطلبات: مخطط ← قيد التنفيذ ← منفذ غير متحقق ← متحقق تقنياً ← مقبول وظيفياً. يضاف «محجوب» مع السبب والقرار المرتبط. لا تعني كتابة المعيار نجاحه.
- يبدأ كل متطلب هنا بحالة **مخطط / غير منفذ / غير مختبر**. المعايير المشروطة بقرار لا تعتمد نتائجها المالية قبل حسمه.
- في كل تغيير لاحق: نربط المتطلب بمعرّفه، ونوثق الملفات والاختبارات والنتائج والقيود. تبقى المعرفات ثابتة؛ الإضافة تأخذ معرفاً جديداً، وإلغاء مطلب يحتاج سبباً وموافقة مسجلة.
- موافقة المستخدم على بدء التوثيق لا تُعد موافقة على توصيات مالية جديدة. تُسجل الإجابات اللاحقة مع تاريخها ونص القرار والمتطلبات المتأثرة.

## نطاق تسليم P01 التاريخي

الخطوة الأولى تضيف هذه الملفات فقط. لا إنشاء Solution أو Migrations أو خدمات أو شاشات هنا. المستندات الأصلية محفوظة دون تعديل. لا حذف لمخرجات `src/` و`tests/` غير المتتبعة، ولا Commit أو Push أو Pull Request ضمن هذا التسليم.

وصلت إجابات المستخدم وسجلت كمصدرU2: اليمن، وعملات يمني وسعودي ودولار قابلة للإضافة مع تحديد أسعار التحويل، وضريبة اختيارية، وتسديد بعملة مختلفة منذ الإصدار الأول. ثم اعتمدU3 الجرد المستمر صراحة. DEC-001،002،003 معتمدة في النطاق/الأساس وتبقى تفاصيلها المالية المذكورة مفتوحة. بقية المسائل غير المجاب عنها تبقى معلقة، ولا تتوقف إعادة تنظيم المتطلبات عليها.
