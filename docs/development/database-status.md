# تقدم P03 — قاعدة التاجر والفروع والتهيئة والأمن الأولي

## متابعة GitHub Actions بعد رفع a38318e

كشف سجل تشغيل 44cd5d5 الذي قدمه المستخدم أن الحاوية running وOOM=false، وأن SQL رفض الاتصال مراراً بالخطأ 17821: لا توجد شهادة TLS صالحة لاتصالات Strict/TDS 8. لذلك لم تبدأ اختبارات SQL. عُدّل توليد شهادة الاختبار لإصدار شهادة خادم من CA محلية مؤقتة، مع CA:FALSE وserverAuth وdigitalSignature/keyEncipherment وSAN لـlocalhost و127.0.0.1. تبقى Encrypt=Strict وTrustServerCertificate=False وتثبيت شهادة الخادم كما هي. لا يثبت السجل وحده أي امتداد كان سبب الرفض تحديداً؛ يعالج التغيير مواصفات الشهادة ويتطلب تأكيد اتصال SQL في التشغيل التالي.

تحقق OpenSSL المحلي من سلسلة التوقيع وصلاحية الشهادة للخادم والاسم localhost، ورفض اسماً مخالفاً، وتطابق المفتاح العام مع الخاص، ومنع قراءة مفاتيح CA والخادم لغير المالك. لم تتغير الحزم أو النماذج أو البيانات. هذه نتائج تحقق الشهادة فقط؛ نجاح SQL واختبارات القاعدة ينتظر GitHub Actions.

أظهر التشغيل الأول الذي شارك المستخدم نتيجته نجاح مهمتي verify على Windows وUbuntu، وفشل sql-integration في خطوة بدء الخادم قبل تشغيل اختبارات SQL. أكد السجل تنزيل الصورة الرسمية والتحقق من بصمتها بنجاح، ثم انتهاء مهلة جاهزية SQL؛ السبب التفصيلي لم يظهر لأن المساعد كان يخفي مخرجات probe وسجل الحاوية. هذا عائق جديد منفصل عن حجب التنزيل المحلي، ولا يثبت فشل Migrations أو نجاحها.

أضيف تشخيص محدود عند فشل الجاهزية: آخر نتيجة probe، وحالة الحاوية ورمز خروجها وOOM، وآخر 80 سطراً من سجلها، مع إخفاء كلمة مرور الاختبار وسلسلة الاتصال، دون طباعة بيئة الحاوية. اختبر إخفاء الاعتماديات وتحمل تعذر جمع التشخيص محلياً باستخدام مخرجات مصطنعة؛ لم يشغل SQL محلياً. لم يعطل TLS ولم تتغير مهلة الجاهزية أو قواعد المحاسبة. ينتظر التصحيح تشغيل GitHub التالي لتحديد السبب الفعلي ومعالجته قبل اعتماد P03.

التاريخ: 2026-10-30. الفرع: Feature-account-system. المرحلة **غير مكتملة التحقق**؛ يجب تنفيذ اختبارات SQL الثلاثة عشر قبل اعتبار القاعدة جاهزة أو الانتقال إلى عمليات P04 المالية.

## ما أضيف في الكود

- توثيق U7 وDEC-005 المحدّث: قاعدة مستقلة لكل تاجر ومنشأة واحدة تدعم عدة فروع، وتبدأ بفرع واحد. استبدل ذلك تفسير U6 السابق، مع حفظ المصادر التاريخية.
- نماذج EF Core و21 جدولاً وثلاث Migrations: الإنشاء، وحماية التدقيق، وإتاحة عدة فروع مع حفظ البيانات والهويات السابقة. بقيت أسماء الجداول الأصلية واستكمالات القيود والتزامن والتوقيت.
- Seed قابل للتكرار دون اختلاق بيانات عميل أو أسعار صرف أو حسابات دخول.
- مالك أولي لمرة واحدة وBCrypt ومنح مطابقة لصلاحيات محددة ومصادقة وتدقيق أوليان. إعداد الشركة والفرع الأول داخل معاملة واحدة، وإضافة فروع أخرى بخدمة مصرح بها وتدقيق داخل معاملتها.
- أداة HisabTak.Tools للإدارة واتصال يشترط التشفير والتحقق من الشهادة.
- نسخ SQL أصلي مع CHECKSUM والتحقق، واستعادة إلى قاعدة جديدة دون استبدال الأصل؛ يحتاجان اختباراً فعلياً.
- مساعد خادم اختبار بشهادة مثبتة وبيانات اعتماد عشوائية خاصة، ومهمة CI منفصلة؛ لم ينفذا حتى النهاية بعد.

## شرط الاستئناف

حُفظ westcentralus.data.mcr.microsoft.com في مسودة إعدادات البيئة لأن صورة Microsoft الرسمية تحول التنزيل إليه. أكدت قراءة سياسة البيئة في 2026-10-30 أن قائمة المضيفين الإضافيين ما زالت فارغة والسياسة المقيدة مطبقة. يلزم حفظ الإضافة وتطبيقها من إعدادات البيئة، ثم تنزيل الصورة وتشغيل المساعد والاختبارات الثلاثة عشر. هذا إعداد لبيئة التطوير فقط ولا يجعل المنتج معتمداً على الإنترنت في التشغيل المحلي.

بعد فتح الاتصال، يشخّص أي خطأ في الحاوية أو الشهادة أو Migrations ويصحح قبل ادعاء النجاح. لا يعوض Mock أو InMemory اختبار SQL الفعلي. لا يبدأ ترحيل P04 فوق قاعدة غير متحققة.
