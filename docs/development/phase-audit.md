## بوابة التكلفة والتجارة قبل التوسع

1. حفظ شراء10×20 ثم10×30:20 وحدة وقيمة500؛ إعادة فتح الفاتورتين تبقي20 و30، وحركات200 و300 وقيد المخزون500. الاختبار الجديد يغطي أيضاً العكس بتاريخ لاحق مع بقاء تقرير التاريخ السابق500.
2. تسجيل الأسعار لا يعني FIFO. مع المتوسط تكلفة الوحدة قبل البيع25؛ مع آخر شراء تستخدم الخوارزمية30 للصرف وتثبت فرقاً بحساب التسوية عند استنفاد/تجاوز القيمة الدفترية. مثلاً صرف20 قد يعطي تكلفة600 وتسوية100 ومخزوناً صفراً. يلزم اختبار SQL صريح وتوضيح التقرير لهذه الفروق قبل قبول طريقة آخر شراء كاملة؛ لا نعرض600 بوصفه تكلفة شراء فعلية ولا نبدل السياسة بصمت.
3. يلزم توسيع مصفوفة SQL: سعر صاعد وهابط، صرف جزئي وكامل، وحدات كسرية، مردود شراء بعد تغير السعر، عكس بعد عمليات تابعة، ومطابقة المخزون مع الدفتر في كل خطوة. الاختبارات الحالية لا تبرر ادعاء اكتمال هذه المصفوفة.
4. فصل حساب مردود المبيعات في إعدادات الفرع والترحيل والتقرير، مع حماية إعدادات ذات التاريخ. حالياً يُعكس حساب المبيعات نفسه؛ صافي الإيراد صحيح حسابياً لكن التفصيل المطلوب في SC-08 ناقص.
5. إكمال عرض تاريخ مشتريات مجمع بالصنف/الفترة وترقيم الصفحات والبحث: يمكن فتح الفواتير المحفوظة الآن، لكن ذلك ليس تقرير تاريخ أسعار شامل. قائمة الواجهة الحالية تعرض أول50 مستنداً.
6. بعدها تنفيذ دورة Windows مع SQL حقيقي للحفظ والترحيل والرفض والعكس والسداد والطباعة، وإقفال P06/P07 بالنتائج قبل POS والتقارير الموسعة. لا ننقل النقص إلى main باعتباره منجزاً.
