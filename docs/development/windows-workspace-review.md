# مراجعة واجهة المستندات على Windows — 2026-11-01

## النطاق المنفذ

واجهة عربية RTL للدخول، والفروع المصرح بها، وقائمة مستندات بصفحات من 50 عنصرًا، وتفاصيلها، وتحرير المسودة بإصدار لكشف التعارض. الأنواع المدعومة: يومية، افتتاحي، قبض، صرف. الاستراتيجيات الأربع مسجلة في DI، وتعيد الخدمة التحقق منها عند الحفظ والترحيل؛ النوع غير المدعوم يرفض.

الترحيل والعكس والأرقام والتدقيق تعمل من المنسق نفسه. المعاينة تعرض **النسخة المحفوظة**؛ للمستند المرحل تعرض السطور المخزنة والقيمة الدفترية وسطر فرق التقريب. الطباعة من قارئ المستند لا تستدعي أي خدمة كتابة. القالب معاينة تشغيلية عامة وليس نموذج فاتورة ضريبية أو حرارية نهائيًا.

الإعداد من الواجهة: إنشاء حساب للفرع مع تصنيف اختياري بصورة ذرية، واختيار عملة الأساس وحساب فرق التقريب، وإنشاء فترة واختيارها وإقفالها وإعادة فتحها. الخدمات تتحقق من الصلاحيات؛ ظهور زر لا يمنح حق العملية. حساب جانب النقد في سند القبض/الصرف يجب أن يكون مصنفًا CASH أو BANK. هذه سندات بسيطة بعملة واحدة، **ليست تسديد ذمة أو توزيع دفعة على فواتير**.

## تشغيل النسخة للمراجعة

1. من تشغيل GitHub Actions الناجح، نزّل artifact باسم `HisabTak-Windows-preview` وفك الضغط كله في مجلد واحد. هذه نسخة تعتمد على وجود .NET 10 Desktop Runtime على Windows؛ ليست مثبتًا نهائيًا أو نسخة ذاتية الاحتواء.
2. جهّز قاعدة SQL Server اختبارية تخص التاجر، وطبّق migrations حتى `20261101000300_EditableDocumentsAndVouchers` ثم Seed. على قاعدة موجودة، أداة `migrate` تطلب مسار نسخة احتياطية جديداً قبل الترقية. لا تستعمل قاعدة العمل اليومية لاختبار الحزمة أول مرة.
3. عبر أداة HisabTak.Tools الموجودة في المستودع، أنشئ المالك بـ`init-owner` والمنشأة والفرع بـ`init-company` إن كانت القاعدة جديدة. لا يوجد اسم مستخدم أو كلمة مرور افتراضيان.
4. حدد الاتصال بالطريقة القائمة: متغير البيئة `HISABTAK_Database__ConnectionString`، أو ملف `appsettings.local.json` إلى جوار exe بمفتاح `Database:ConnectionString`. استعمل اتصالاً مشفراً مع التحقق من شهادة SQL. لا ترفع كلمة مرور أو ملف اتصالك إلى Git.
5. شغّل `HisabTak.WPF.exe` وسجل الدخول. اختر الفرع. أنشئ الحسابات والفترة، وحدد عملة الأساس وحساب فروق التقريب قبل أول ترحيل.

صيغة ملف الإعداد المحلي، تستبدل القيم في جهازك فقط:

```json
{
  "Database": {
    "ConnectionString": "Server=YOUR_SQL_SERVER;Database=YOUR_TEST_DATABASE;Integrated Security=True;Encrypt=True;TrustServerCertificate=False"
  }
}
```

ومن مصدر المشروع بعد تثبيت SDK المثبت في global.json:

```powershell
dotnet restore HisabTak.slnx --locked-mode
dotnet run --project src/HisabTak.Tools -- seed
dotnet run --project src/HisabTak.WPF
```

الأمران الأخيران يفترضان ضبط متغير الاتصال وتهيئة القاعدة والمالك والمنشأة مسبقاً. لا تجري الواجهة ترقية تلقائية للقاعدة عند الدخول.

## سيناريو قبول محلي قبل main

| التجربة | النتيجة المطلوبة |
|---|---|
| الدخول الخاطئ أو غياب إعداد الاتصال | رفض واضح دون عرض كلمة مرور أو سلسلة الاتصال |
| الدخول بمستخدم فرع محدود | لا تظهر فروع أخرى؛ الخدمة ترفض الوصول إليها أيضاً |
| إنشاء مسودة متوازنة وحفظها | تبقى مسودة بلا رقم ترحيل أو قيد مالي |
| فتح المسودة من نافذتين وتعديل مختلف في كل منهما | أول حفظ ينجح؛ الحفظ المتعارض يطلب إعادة تحميل النسخة الحالية |
| تعديل المحرر ثم محاولة ترحيل النسخة القديمة | تطلب الواجهة حفظ التعديلات أولاً؛ الإصدار المتعارض يرفض في الخدمة |
| ترحيل المسودة وإعادة الطلب | رقم وقيد واحدان فقط، والمحرر يصبح للقراءة |
| قبض بصندوق مدين / صرف بصندوق دائن | يقبل التصنيف الصحيح؛ يرفض حساباً غير مصنف أو عملة مخالفة |
| الإقفال ثم محاولة قيد جديد في الفترة | رفض، دون قيد جزئي أو رقم جديد محفوظ |
| عكس مستند في تاريخ مفتوح وإعادة الطلب | عكس واحد مرتبط، والرقم الأصلي محفوظ |
| معاينة مستند مرحل ثم إلغاء الطباعة أو إعادة الطباعة | لا قيد أو رقم جديد؛ تحقق يدوياً من وضوح العربية ومقاس الورق |
| إغلاق المحرر مع تغيير غير محفوظ | يظهر تأكيد قبل فقد التعديل |

## ما تثبته الاختبارات وحدودها

SQL يختبر الخدمات الفعلية والمهاجرات والتزامن والتراجع والتكرار وعزل الفروع. فحص WPF على Windows ينشئ النافذة فعلياً، ويختبر RTL وحالة الدخول وغياب الاتصال، ويحفظ مسودة عبر خدمات بديلة، ثم يفتح مستنداً مرحلاً ويتحقق من تعطيل التعديل. تحفظ صور `wpf-smoke-screenshots` لحالة الدخول والمحرر.

الفحص البصري/التفاعلي على جهاز المستخدم مع SQL الفعلي والطابعة ما زال مطلوباً؛ خدمات الواجهة البديلة لا تثبت اتصال قاعدة العميل أو طبع الورق. نجاح build ليس ضماناً لغياب جميع الأخطاء.

## ما لا يغلق بهذه الحزمة

باقي الأنواع العشرين المرجعية ليست عشرين حالة استخدام مكتملة. البيع والشراء والمردود والتحويل والجرد تتطلب مخزون P06 ودورة P07، ومستندات النية وPOS والتخليص تتبع P09؛ لا تظهر كخيارات تشغيلية ناقصة. سياسات تكلفة المخزون والسالب والأثر الرجعي والدفعات تحتاج حسم DEC-003/011 قبل تنفيذ آثارها. لذلك لا يوصَف النظام كله بأنه جاهز للإنتاج أو خالٍ من الأخطاء، ولا تدمج main تلقائياً بناء على وجود هذه الواجهة.


تفاصيل القرارات المتبقية مع أمثلة ملموسة في [بوابة مستندات المخزون](inventory-entry-decisions.md). هذه قرارات تؤثر على قيمة المخزون والربح، وليست طلب إذن جديد لكتابة الكود المعتمد.
