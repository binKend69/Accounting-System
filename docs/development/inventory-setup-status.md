# تهيئة المخزون — P06، حزمة البيانات المرجعية

أضيفت خدمة `IInventorySetupService` وواجهة عربية لإنشاء الوحدات والمستودعات ومواقع التخزين وقراءتها. تستخدم الجداول المرجعية الموجودة، ولا تحتاج Migration جديدة؛ آخر Migration تبقى `EditableDocumentsAndVouchers` (10 migrations).

- الوحدات مشتركة للمنشأة، والمستودع مرتبط بفرع، والموقع بمستودع نشط في الفرع نفسه. لا تعرض الشاشة المستودعات القديمة ذات الفرع الفارغ تلقائياً؛ يلزم تصحيحها ضمن ترقية مدروسة إذا وجدت بيانات منها.
- تتطلب القراءة والإنشاء `SETUP.MANAGE`. تطبق الخدمة سياسة الوصول للفروع الحالية: فرع المستخدم أو `ACCOUNTING.BRANCH.ALL` الصريحة؛ المستخدم بلا فرع ليس مستخدماً لكل الفروع تلقائياً.
- تقص المسافات الخارجية وتتحقق من طول الاسم: 50 للوحدة و100 للمستودع والموقع. الاسم محجوز داخل نطاقه حتى إن عطل السجل أو حذف منطقياً.
- تمنع الخدمة الإنشاء المتزامن المكرر بقفل SQL معاملاتي ومقارنة وفق Collation قاعدة البيانات. هذه حماية لمسار الخدمة، وليست قيد تفرد جديداً على الجداول القديمة؛ إدخال SQL مباشر لا يمر بها.
- الإنشاء وسجل التدقيق في معاملة واحدة، وفشل التدقيق يتراجع عن الإنشاء. إعادة محاولة اسم موجود ترفض دون إنشاء سجل آخر.
- الشاشة تحمل البيانات صراحةً بزر «تحميل بيانات الفرع». تمسحها عند تغيير الفرع والخروج، وتعرض مواقع المستودع المختار فقط. لا تتطلب شاشة المستندات صلاحية تهيئة المخزون عند تسجيل الدخول.

## قبول محلي

1. جهّز قاعدة الاختبار وفق `windows-workspace-review.md` وسجل الدخول بحساب مصرح.
2. افتح «تهيئة المخزون»، وحمّل بيانات الفرع، وأنشئ وحدة ثم مستودعاً ثم موقعاً باسمه المختار.
3. كرر الاسم مع مسافات خارجية؛ يجب رفض التكرار. اختبر الاسم نفسه لمستودعين في فرعين مختلفين؛ هو مسموح.
4. بدّل المستودع ثم الفرع، وتأكد من عدم ظهور مواقع فرع آخر. سجل الخروج وتأكد من مسح القوائم.
5. اختبر حساباً بلا صلاحية الإعداد؛ يجب رفض التحميل والإنشاء من الخدمة أيضاً.

## حدود الحزمة ونقطة الاستكمال

هذه بداية P06 وليست إغلاقها: لا توجد بعد أصناف أو تحويلات وحدات أو أرصدة أو دفعات أو حركات مخزون أو تكلفة بضاعة. الشاشة تدعم الإنشاء والعرض فقط؛ تعديل وتعطيل المرجع من الواجهة يحتاجان إصداراً متوقعاً وفحص الارتباطات عند إضافة الأصناف والحركات. لا توجد فواتير بيع/شراء/مردود متكاملة بعد، ولا تسديد ذمم مخزن.

لم تحسم إجابة صريحة التفاصيل الثلاثة في `inventory-entry-decisions.md` (نطاق التكلفة، الأثر الرجعي، اختيار الدفعات)، ولذلك لا تنشئ هذه الحزمة أثراً مالياً أو مخزنياً يفترض تلك السياسات. لا يعد طلب المتابعة العام موافقة على اختيار تفصيلي غير محدد.

اختبارات SQL الجديدة تغطي نطاق الفرع والمستودع المعطل، الأسماء المتزامنة والمحذوفة، الصلاحيات، وتراجع التدقيق. فحص WPF يستخدم خدمات بديلة ويختبر إرسال الاسم والمستودع ومسح بيانات الخروج؛ لا يستبدل تجربة Windows مع SQL حقيقي.
